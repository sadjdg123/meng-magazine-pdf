# 图片检索与素材记录

## 默认路径

封面用当前环境的imagegen生成本次主题的原创概念插画，上方留标题空间。内页照片来自用户实拍或网络上的真实照片；AI封面素材不能嵌入内页。准确的数据图和流程图可用代码绘制。用户对封面有明确要求时遵从本次指令。

网络取图先搜具体地点、对象、事件；打开原始网页核实主体、拍摄地、可查日期、作者与使用条件，再下载原图。搜索缩略图、未经核实的转载和仅凭标题判断的图片不能作为成品素材。无法确认时用无图版式或说明素材缺口。历史图不能称为当前现场。

把每张图片加入顶层assets列表。程序验证记录是否齐备，但不能自动证明照片真实或许可有效；这些需要查源页面与查看图片。不要为了通过检查填写虚构记录。

## 记录字段

必需：id（唯一）、path（相对JSON或绝对路径）、kind、subject、author、license。

kind：photo（网络真实照片）、user_photo（用户实拍）、ai_cover（AI封面）、graphic（准确信息图或明确标注的技术测试图）。photo另需source_url原始页面；用户照片记录用户提供及授权用途，不编造网络地址。

按实际情况补充：source_url、license_url、date、changes、protected_bounds。开放许可注明完整名称及许可链接；需要授权的照片须有实际许可依据，不能把“来自网络”填成许可。尊重署名、相同方式共享等实际条件。无法确认可用性就不嵌入。

```
{
  "id": "canal",
  "path": "images/canal.jpg",
  "kind": "photo",
  "subject": "日本小樽运河夜景",
  "author": "Haha169",
  "license": "CC BY-SA 4.0",
  "license_url": "https://creativecommons.org/licenses/by-sa/4.0/",
  "source_url": "https://commons.wikimedia.org/wiki/File:Otaru_Canal_Night.jpg",
  "date": "2016-02-16",
  "changes": "缩放与跨页裁切"
}
```

例子对应随附旅行示例；新题材不得冒用。模块image填写素材id即可；article图片的path也可填id。还支持与assets记录对应的文件路径。

## 裁切、清晰度与来源页

图片先处理EXIF方向，始终保持比例裁切，不拉伸。focus为0–1范围的[x,y]，决定裁切窗口；图片原图不修改。按显示大小以144 ppi为上限生成嵌入JPEG，质量86，不放大源像素。低于96 ppi警告、低于72 ppi停止；换清晰原图或较小图窗。参数在assets/style.json。

跨页一次裁出完整窗口，再分别显示左右部分，避免两页各自裁切。若重要人物/主体有已知范围，可填protected_bounds：源图经EXIF校正后的归一化矩形[x0,y0,x1,y1]列表。被裁掉或穿过中缝会警告。程序不做人脸识别；没有主体框时也必须人工检查最终跨页组合。

默认自动插入“图片来源与许可”模块，通常在封底前，可自然续页，并保留可点击来源和许可链接。include_sources=false仅用于复现历史样张或用户明确要求把完整来源另放封底/附录；不得因此省略需要的署名与许可信息。

重复用同一素材跨不同模块会警告；确有编辑需要时在模块注明repeat_reason并复核。一张照片连续跨页属于一次使用。双图页优先两张不同的实拍，避免反复换裁切充页。

最终QA列出实际嵌入像素、有效ppi、图片哈希、素材记录与警告。所有警告逐项判断，不能只看missing_text为空就交付。
